# Release Checklist

Use this before calling a Blackhatbadshah milestone or release ready.

## Engineering

- [ ] Build succeeds from a clean checkout.
- [ ] Relevant tests pass.
- [ ] Known limitations are documented.
- [ ] Breaking changes are called out.
- [ ] Security-sensitive changes are reviewed.

## Evidence

- [ ] Reproduction or verification commands are recorded.
- [ ] Important logs or measurements are sanitized and reproducible.
- [ ] Performance claims include methodology and context.
- [ ] The release notes distinguish implemented, partial, and planned behavior.

## Documentation

- [ ] README reflects the current state.
- [ ] Architecture changes are documented.
- [ ] Build or migration instructions are current.
- [ ] A useful technical artifact exists for the most important change.

## Communication

- [ ] Release notes explain what changed and why.
- [ ] No fabricated metrics, endorsements, or popularity claims.
- [ ] External announcements link to the canonical repository artifact.

## Final rule

Do not hide unfinished work. Label it accurately.

A credible project can be incomplete. It cannot be misleading.
