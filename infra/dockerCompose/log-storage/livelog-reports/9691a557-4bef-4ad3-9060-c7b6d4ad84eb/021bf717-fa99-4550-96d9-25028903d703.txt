## 6. REMEDIATION PLAN

### Immediate Actions

- **Block malicious IPs** at the firewall or via `fail2ban`.
- **Enforce SSH key-based authentication**; disable password-based login.
- **Limit SSH access** to known IP ranges if possible.

### Short-term Fix

- Install and configure `fail2ban` to automatically block IPs after failed attempts.
  ```bash
  sudo apt install fail2ban
  sudo systemctl enable fail2ban
  sudo systemctl start fail2ban
  ```

### Long-term Solution

- **Disable root login over SSH**:
  ```bash
  PermitRootLogin no
  ```
- **Use non-standard SSH port** (e.g., 2222).
- **Implement two-factor authentication (2FA)** for SSH.

### Code/Config Changes

- Update `/etc/ssh/sshd_config`:
  ```bash
  PasswordAuthentication no
  PermitRootLogin no
  Port 2222
  ```

### Monitoring Recommendations

- Set up alerts for:
  - More than 5 SSH failed login attempts in 1 minute.
  - New SSH connections from unknown IPs.
- Use tools like `fail2ban`, `logwatch`, or centralized logging with **ELK Stack** or **Splunk**.

## 7. PREVENTIVE MEASURES

- **Architectural Improvements**:
  - Place SSH behind a **bastion host** or **VPN**.
  - Use **cloud security groups** to restrict SSH access.

- **Logging Enhancements**:
  - Include **GeoIP data** in logs to identify attack origins.
  - Log **successful logins** with user session details.

- **Testing Gaps**:
