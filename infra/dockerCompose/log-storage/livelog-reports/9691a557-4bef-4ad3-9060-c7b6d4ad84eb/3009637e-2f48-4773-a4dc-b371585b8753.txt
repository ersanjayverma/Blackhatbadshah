## 6. REMEDIATION PLAN

### Immediate Actions:
- **Implement fail2ban** to automatically block attacking IPs
- **Rate limit SSH connections** using iptables
- **Temporarily block high-risk IP ranges** if business permits

### Short-term Fix:
- **Configure fail2ban with SSH jail**:
  ```bash
  # Install fail2ban
  sudo apt install fail2ban
  # Configure jail.local with SSH settings
  [sshd]
  enabled = true
  port = ssh
  filter = sshd
  logpath = /var/log/auth.log
  maxretry = 3
  bantime = 3600
  ```

### Long-term Solution:
- **Implement SSH key-only authentication**
- **Change default SSH port** from 22 to non-standard port
- **Deploy network-level security groups** to restrict SSH access
- **Enable two-factor authentication** for SSH

### Code/Config Changes:
```bash
# /etc/ssh/sshd_config improvements
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
Port 2222  # Change from default 22
AllowUsers your_admin_user
MaxAuthTries 3
ClientAliveInterval 300
ClientAliveCountMax 2
```

### Monitoring Recommendations:
- **Alert on**: >5 failed SSH attempts in 1 minute
- **Alert on**: Any root login attempts
- **Alert on**: New geographic login patterns
- **Dashboard**: SSH attack map with IP geolocation
