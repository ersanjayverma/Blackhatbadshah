## 6. REMEDIATION PLAN

### Issue 1 – Permission error on `/opt/bhbworker/.bhb-worker-id`

| Stage | Action | Detail |
|-------|--------|--------|
| **Immediate** | Stop the restart loop to prevent journal flooding. | ```bash\nsystemctl stop bhbworker.service\nsystemctl reset-failed bhbworker.service\n``` |
| **Short‑term Fix** | Correct file/directory ownership & permissions. | ```bash\n# Assuming the service runs as user `bhbworker` (or `appuser`)\nchown -R bhbworker:bhbworker /opt/bhbworker\nchmod 750 /opt/bhbworker\n# Ensure the id file is writable (or absent so it can be created)\nrm -f /opt/bhbworker/.bhb-worker-id   # optional if stale\ntouch /opt/bhbworker/.bhb-worker-id\nchmod 640 /opt/bhbworker/.bhb-worker-id\n``` |
| **Short‑term Verification** | Restart the service and confirm it stays up. | ```bash\nsystemctl start bhbworker.service\nsystemctl status bhbworker.service\njournalctl -u bhbworker -f\n``` |
| **Long‑term Solution** | Harden deployment scripts / package to set correct permissions during install. | - Add a `postinst` script (dpkg) or `install` step in CI that runs `chown`/`chmod`.<br>- In the service unit, explicitly set `User=` and `Group=` matching the file owner.<br>- Modify the application to **fall back** if the file cannot be written (e.g., generate a temporary ID in `/run` or `/var/lib/bhbworker`). |
| **Code/Config Changes** | - In `LogPusherService.GetOrCreateWorkerId()`, wrap the write in a try/catch and log a clearer message; consider using `Path.GetTempFileName` in a writable directory if the target path is not permissive.<br>- Update `bhbworker.service` unit file: <br>```ini\n[Service]\nUser=bhbworker\nGroup=bhbworker\nRuntimeDirectory=bhbworker\nRuntimeDirectoryMode=0750\n``` |
| **Monitoring Recommendations** | - Alert on `systemd` service state transitions to `failed` or rapid restart loops (`RestartCount > 5` within 1 min).<br>- Alert on `UnauthorizedAccessException` patterns in the journal (`journalctl -u bhbworker | grep -i unauthorized`).<br>- Add a file‑system permission health check (e.g., a cron/scrape job that attempts to `touch /opt/bhbworker/.test-perm`). |

## 7. PREVENTIVE MEASURES

1. **Infrastructure‑as‑Code (IaC) enforcement** – Ensure the directory `/opt/bhbworker` and its contents are always created with the correct ownership/permissions via Terraform, Ansible, or Cloud‑Init.  
2. **Service‑unit hardening** – Use `ProtectSystem=full` and `ReadWritePaths=/opt/bhbworker/.bhb-worker-id` in the systemd unit to whitelist only the required writable path, preventing accidental permission drift.  
3. **Automated post‑deploy tests** – After any deployment, run a health‑check that invokes the binary with `--dry-run` to confirm it can create/read the worker‑ID file.  
4. **Enhanced logging** – Emit a structured log (`JSON`) at service start that includes the effective UID/GID and a checksum of the config directory to quickly spot permission mismatches.  
5. **Capacity‑aware restart policy** – Change `Restart=on-failure` to `Restart=on-abnormal` with `StartLimitBurst=5` and `StartLimitIntervalSec=300` to avoid endless restart storms while still allowing a few retries.
