## 6. REMEDIATION PLAN

### Issue: Brute-force SSH Attacks

- **Immediate Actions**:
  - Block offending IPs via `fail2ban` or firewall rules.
  - Temporarily reduce `MaxStartups` limit to prevent resource exhaustion.

- **Short-term Fix**:
  - Deploy `fail2ban` to automatically ban IPs after failed attempts.
  - Enforce key-based SSH authentication and disable password auth.

- **Long-term Solution**:
  - Implement a VPN or bastion host for SSH access.
  - Rotate SSH ports and use non-standard ports.

- **Code/Config Changes**:
  ```bash
  # /etc/ssh/sshd_config
  PasswordAuthentication no
  PermitRootLogin no
  AllowUsers admin
  ```

- **Monitoring Recommendations**:
  - Alert on >5 failed SSH attempts in 1 minute.
  - Dashboard for SSH login success/failure rates.

---

## 7. PREVENTIVE MEASURES

- **Architectural Improvements**:
  - Use **SSH key-only authentication**.
  - Restrict SSH access via **security groups** or **firewall rules**.
- **Additional Logging**:
  - Log geo-IP data for login attempts.
  - Enable audit logs for all `sudo` commands.
- **Testing Gaps**:
