## 6. REMEDIATION PLAN  

### Issue 1 – Brute‑Force SSH Attempts  
| Action | Detail |
|--------|--------|
| **Immediate** | - Add a temporary **Rate‑Limit** rule to `sshd` (e.g., `iptables -A INPUT -p tcp --dport 22 -m recent --name SSH --set -j DROP` with appropriate thresholds). <br> - Enable **fail2ban** with a jail for `sshd` (bantime = 1 day, maxretry = 3). |
| **Short‑term** | - Disable **password authentication** for SSH (`PasswordAuthentication no`) and enforce **public‑key only** for all users. <br> - Ensure `root` login is prohibited (`PermitRootLogin no`). |
| **Long‑term** | - Move SSH to a **non‑standard port** or place it behind a **VPN/Jump host**. <br> - Implement **MFA** for privileged accounts. |
| **Code/Config** | Edit `/etc/ssh/sshd_config`:<br>```ini\nPasswordAuthentication no\nPermitRootLogin no\nAllowUsers sj\n```<br>Restart `sshd`. |
| **Monitoring** | - Alert on > 10 failed `sshd` logins per minute. <br> - Alert on any successful login from IP not in approved CIDR list. |

### Issue 2 – UDP Flood (port 2055)  
| Action | Detail |
|--------|--------|
| **Immediate** | - Verify that UDP 2055 is **not required**; keep the existing UFW block. |
| **Short‑term** | - Rate‑limit inbound UDP on that port at the network firewall (`iptables -A INPUT -p udp --dport 2055 -m limit --limit 1/s -j ACCEPT`). |
| **Long‑term** | - If a legitimate service ever needs it, move it to a **dedicated VLAN** or **private IP** not reachable from the internet. |
| **Monitoring** | - Alert on spikes > 1000 UDP packets/sec to any blocked port. |

### Issue 3 – Unexpected SSH Login (`sj`)  
| Action | Detail |
|--------|--------|
| **Immediate** | - Verify the identity of user `sj` (owner, purpose, MFA). <br> - Check `last` / `who` for recent activity. |
| **Short‑term** | - Enforce **public‑key** authentication for `sj`. <br> - Enable session recording (`auditd` or `tlog`) for later forensic review. |
| **Long‑term** | - Periodic **user access review** (least‑privilege). |
| **Monitoring** | - Alert on any new user creation or grant of sudo privileges. |

## 7. PREVENTIVE MEASURES  

1. **Zero‑Trust Network Segmentation** – isolate management interfaces (SSH) on a dedicated management VLAN or VPN.  
2. **Comprehensive Logging** – ship `auth.log` to a centralized SIEM; enable `logwatch` or `OSSEC` for pattern detection.  
3. **Automated Threat Intelligence** – integrate fail2ban with IP reputation feeds (e.g., AbuseIPDB).  
4. **Regular Audits** – schedule quarterly reviews of user accounts, SSH keys, and firewall rules.  
5. **Patch Management** – ensure `openssh-server` and `ufw` are up‑to‑date with security patches.
